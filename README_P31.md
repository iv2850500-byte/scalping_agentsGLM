## Главная находка: edge-гейт v3-конфига математически недостижим

Цепочка из живого кода [ФАКТ: momentum.rs, config_tao_momentum_v3.toml]:
- tp_pct = max(atr*2.5, fee-пол, min_tp 0.020).min(0.02) → **всегда ровно 2%**
  (min_tp=cap=2% зажимают значение с двух сторон);
- sl_pct = 0.02 / rr_ratio = 0.02 / 1.5 = 1.3333%;
- net_rr = (0.02 - c) / (0.013333 + c), где c = 2*fee + spread + funding;
- edge-гейт требует net_rr >= min_net_rr * 1.15 = 1.2 * 1.15 = 1.38
  [ФАКТ: EDGE_QUALITY_MULT=1.15];
- условие net_rr >= 1.38 даёт c <= 0.000672, а 2*fee = 0.001 уже больше
  (fee_rate=0.0005 в конфиге). Даже при нулевом спреде и нулевом funding
  максимум net_rr = 0.019/0.014333 = **1.3256 < 1.38**.

Следствие: под v3-конфигом бот не откроет ни одной сделки — НИКОГДА, на любом
инструменте, при любой волатильности. Это объясняет «тишину» tao_momentum.

Как проверить на живом боте (2 минуты): WebUI diag по tao_momentum — счётчик
`edge=` в строке Momentum(candles) diag v3full должен расти со временем, а
сделок нет. В WFA-воронке то же: `rr=0 edge=222 passed=0` (taofull).

Исправление, если momentum когда-нибудь захотят вернуть в строй (решение не
сейчас, стратегия выбыла): rr_ratio >= 2.0 ИЛИ min_net_rr <= 1.0 ИЛИ убрать
edge-множитель. Но даже торгуемые варианты в минусе (см. плато) — чинить
конфиг бессмысленно, пока не переделана сама логика входа.

## Кросс-валидация порта (почему результату можно верить)

Порт проверен независимой второй реализацией (Python-референс, в пакет не
входит — тебе Python не нужен, сверка сделана на стороне ассистента):
- per_fold.csv 1:1 по всем фолдам: taofull (28), tao450 (11), btc450 (11);
- сделки 1:1 ПОСТРОЧНО: 159/159 на taofull (rr2.0), 76/76 на tao450 (rr2.0);
- bootstrap-CI 1:1 (MT19937 бит-в-бит совместим с CPython random.Random);
- поймана и устранена ловушка: Python round() — банкирское округление,
  Rust f64::round (живой math.rs round_to_tick) — от нуля; сделка 4 эталона
  (sl_raw 308.385) расщепляла реализации: 308.39 (Rust=живой движок) против
  308.38 (Python). Референс приведён к семантике живого движка, после чего
  расхождений 0.

## Что НЕ моделировалось (те же упрощения, что в P29/P30 для bounce)

- Оверлеи state_manager: BE=1.5R, chandelier-трейл 2*ATR, TrailExit,
  Timeout/TimeoutFlat (state_manager.rs:318/:517). Эффект смешанный,
  направление смещения не заявляем.
- loss-streak cooldown считается по времени бара (живой бот — wall clock,
  momentum.rs chrono::Utc::now(); на непрерывной сессии эквивалентно).
- Вход по close сигнальной свечи с округлением до tick 0.01 — как живой
  сигнал (signal.price = entry). Замечание аудита: тик BTC захардкожен для
  всех символов, на TAO (~2-5 USDT) округление сдвигает SL/TP до ~0.2% —
  это баг живого кода, в WFA воспроизведён 1:1 (не сглажен).
- Позиция, не закрывшаяся до конца OOS-окна, в сделки не попадает.
- Спред в net_rr — консервативная константа --spread (у живого бота без
  bookTicker было бы 0, с bookTicker — реальный спред; TAO-спред обычно
  шире BTC, т.е. для TAO модель НЕ завышает издержки).
