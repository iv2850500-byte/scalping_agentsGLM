# P69 - runbook тестнет-проверки защитных ордеров (A-04)

Цель: доказать на Binance Futures TESTNET, что защитный (TP/SL) ордер реально
выставляется через Algo API, и в логе нет строки о позиции без биржевого стопа.
Прод-ключи НЕ использовать ни на одном шаге.

## Предпосылки
- Тестнет-аккаунт на testnet.binancefuture.com и ТЕСТОВЫЕ API-ключи
- Ключи передаются только через env/конфиг проекта; не коммитить, не вставлять
  в чат и не печатать в лог
- Минимально возможный размер позиции

## Шаги
1. cargo build --release (или текущий рабочий режим сборки)
2. Запустить бота в тестнет-конфигурации (как настроено в проекте)
3. Открыть одну минимальную позицию, дождаться установки защит
4. Сохранить полный лог в файл (например logs/testnet_p69_<дата>.log)
5. Сверить строки лога с критериями ниже; опционально сверить ордера/позиции
   в интерфейсе тестнета

## Что искать в логе (точные подстроки)
- "поставлен через Algo API (id="            - сработала нижнерегистровая ветка
- "поставлен через Algo API camelCase (id="  - сработала camelCase-ветка P69
- "camelCase Algo тоже отказал (code="       - camelCase отклонён, уход в классику
- "позиция БЕЗ биржевого стопа"              - КРИТИЧНО: защита не встала

## Критерии
- PASS: есть ЛЮБАЯ из двух строк успеха И НЕТ строки "позиция БЕЗ биржевого стопа"
- FAIL: обе строки успеха отсутствуют; записать код из "camelCase Algo тоже
  отказал (code=...)" и/или код классической ветки, приложить лог
- STOP: строка "позиция БЕЗ биржевого стопа" - немедленно остановить бота,
  живую торговлю не включать до разбора

## При FAIL/STOP
1. Остановить торговлю
2. Откат: git revert e68c16b (или файл из backups\P69_surgical_20261115_091354)
3. Прислать полный лог целиком - разбирать причины по кодам ответа биржи
