## Находки аудита ядра (по коду снапшота 2026-11-12)

### A-01. Учёт DCA-лестницы сломан: `add_dca_order` — мёртвый код | КРИТИЧНО
- Где: state/state_manager.rs:892 (определение, 0 вызовов); execution/execution_engine.rs:1488 (`add_position_with_risk` на КАЖДЫЙ вход); strategies/keltner_dca.rs (can_dca=true, 5 ордеров).
- Условия: gold_dca добавляет ордера 2–5 к живой позиции.
- Последствие: `add_position_with_risk` ПЕРЕЗАПИСЫВАЕТ позицию (insert) → в state quantity = объём ПОСЛЕДНЕГО ордера, entry = цена последнего ордера; `global_risk.register_position` тоже перезаписывается → суммарный риск недоучтён; PnL закрытия Exit_KeltnerDca считается от неверного входа (записывается в risk/journal). Само-починка: periodic reconciliation (≤5 мин) синхронизирует qty/entry по бирже при расхождении >5%.
- Проверка: воспроизводится unit-тестом (добавить 2 DCA-ордера, сверить state vs сумму); в логе видно «DCA add» vs «ВХОД ИСПОЛНЕН».
- Статус: **ПОДТВЕРЖДЕНО (код)**. Исправление: в execute_real при существующей позиции этого бота вызывать add_dca_order вместо add_position_with_risk + суммировать риск в global_risk. НЕ применено в P68 (требует правки движка и теста на тестнете).

### A-02. `set_risk_multiplier` — вся «ЭТАП C» деградация риска не работает | ВЫСОКО
- Где: main.rs:1545 (`strategy.set_risk_multiplier(...)`); strategies/mod.rs:99 (дефолт no-op); НИ ОДНА стратегия не переопределяет.
- Последствие: SURVIVAL (0.5) не уменьшает сайзинг; HALT (0.0) работает только потому, что suspended блокирует входы на уровне RiskManager. Заявленное «риск никогда не растёт при падающем EV» в части множителя не выполняется.
- Статус: **ПОДТВЕРЖДЕНО (код, grep)**. Исправление: переопределить set_risk_multiplier в стратегиях (множитель в calc_position_size_with_fees), тест на 0.5/0.0.

### A-03. Риск не резервируется атомарно до ордера; сайзинг не от актуального equity | СРЕДНЕ
- Где: risk/mod.rs:281-365 (check() читает total_risk), engine регистрирует риск ТОЛЬКО после филла (execution_engine.rs:1483); баланс сайзинга = initial_balance + локальный realized_pnl (strategies/momentum.rs:829), get_balance биржи в сайзинге не участвует.
- Последствие: (1) гонка двух ботов между check() и register_position() может кратковременно превысить max_concurrent_risk_pct; (2) после серии убытков/прибылей размер позиции не масштабируется к фактическому equity; (3) ликвидация/плечо/маржа не учитываются (плечо фиксируется вне бота).
- Статус: **ПОДТВЕРЖДЕНО (код)**; компенсации: отдельный RiskManager на бота, ежедневный портфельный стоп P15, SURVIVAL/HALT. Фикс-план: reserve() с таймаутом в GlobalRiskManager + периодический set_equity_base по /fapi/v2/balance.

### A-04. Параметры Algo Order API в нижнем регистре противоречат официальным докам | ВЫСОКО (защиты)
- Где: exchange/binance_futures.rs:177 (`algotype=CONDITIONAL&triggerprice=`).
- Доказательство: developers.binance.com/docs/derivatives/usds-margined-futures (Algo Order, обращение 2026-11-13): эндпоинт POST /fapi/v1/algoOrder существует, параметры `algoType=CONDITIONAL`, `triggerPrice` (camelCase), поддерживает STOP_MARKET/TAKE_PROFIT_MARKET, closePosition, workingType. Комментарий в коде описывает 4 круга валидации тестнета, «требовавших» нижний регистр — обе версии одновременно истинными быть не могут.
- Последствие: если биржа/режим начнёт строго требовать camelCase, основной путь постановки STOP_MARKET/TP_MARKET начнёт отклоняться; останется классический fallback (/fapi/v1/order), исторически на тестнете тоже отклонявшийся → позиция без биржевой защиты (только софт-стоп). Не молчит: «🚨 позиция БЕЗ биржевого стопа» в логе.
- Решение (P69, опциональный пак): добавляет попытку camelCase после отказа нижнерегистровой версии, прежде чем уходить в классику. Статус: **ПОДТВЕРЖДЕНО (расхождение с доками)**; сам P69 — ИСПРАВЛЕНО, НЕ ПРОВЕРЕНО (нужен тест постановки защит на тестнете).

### A-05. persist_positions: await под шардированным read-guard'ом DashMap | НИЗКО

- Последствие: writers (get_mut) блокируются на время БД-записей; deadlock-риска нет (один лок-порядок), но возможны микрозадержки exit-пути. S1-чек: check_and_update_position и остальные мутаторы — синхронные, await под живым guard'ом НЕ обнаружен (искл. A-05).
- Статус: **ПОДТВЕРЖДЕНО (код)**. Фикс: clone снапшота позиций, затем запись без итератора.
