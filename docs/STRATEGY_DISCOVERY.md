# STRATEGY DISCOVERY — протокол пятого бота (P68, 2026-11-13)

## 1. Назначение

Пятый бот = исследовательский процесс, а не управляющий деньгами. Конвейер
`spectrum_lab` (standalone, std-only Rust — путь P33: собирается отдельно от
основного крейта) реализует:

```
QA данных → реестр гипотез (ДО оценки) → walk-forward (параметры только на train)
→ отложенный OOS-holdout (последние 30%, трогается один раз) → стресс издержек ×2
→ гейты → портфельный оверлей (корреляция дневных R) → только после PASS + явного
разрешения пользователя: paper → testnet → ограниченный live (отдельное решение)
```

## 2. Правила отбора (анти-переобучение)

1. Гипотеза регистрируется в `hypotheses_registry.json` (id, класс, сетка
   параметров, FNV1a-хэш данных, seed) **до** расчёта метрик.
2. Отрицательный результат фиксируется и повторной настройке на OOS не
   подлежит: тот же OOS-кусок запрещено использовать как тренажёр.
3. Гейты (P64-стиль): n ≥ 20 (OOS или WF-сумма), WR > breakeven + 3 п.п.,
   ≥ 50% WF-фолдов с R>0, R_oos > 0. PASS только по всем четырём.
4. Интрабар-неоднозначность (SL и TP в одном баре) решается консервативно —
   первым считается SL. Вход — по open следующего бара после сигнала.
5. Отбор не по одному Sharpe: n, WR, PF, maxDD (в R), распределение R по
   фолдам, чувствительность к издержкам (×2), концентрация прибыли.
6. OHLCV не позволяет моделировать очередь лимитных ордеров и точные филлы —
   симуляция намеренно консервативна; заявлять точную доходность запрещено.

## 3. Гипотезы, протестированные в P68 (результаты реальные)

Данные: TAOUSDT-450d, ETHUSDT-450d, BTCUSDT-450d (1h), fee=0.05%,
spread=0.02%, train=2160/test=720/step=720, warm=250, OOS=30%.

| гипотеза | класс | правило | вердикт |
|---|---|---|---|
| H1_range_fade | mean reversion | z-score(LB=20/40) ±2.0/2.5 во флэте (range30<8%), SL 1.2ATR/TP 1.6ATR | **FAIL** на 3 активах: OOS R = −10.3 (TAO), −15.4 (ETH), −14.2 (BTC); WR ниже be+3пп |
| H2_donchian_breakout | breakout | close > Donchian(20/55) пред. баров + volume ≥ 1.1–1.3×avg20; SL 1.5ATR/TP 3ATR | **FAIL** на 3 активах: OOS R = −11.0 (TAO), −4.3 (ETH), −9.7 (BTC) |

Показательный случай: H1@TAO — WF-фолды суммарно +2.29R (in-sample
привлекательно), OOS −10.26R → переобучение поймано, PASS не выдан.

Портфельный оверлей: корреляция дневных R mean-reversion vs breakout
отрицательная (−0.08…−0.53 на одном активе) — диверсификационный потенциал
между КЛАССАМИ существует, но ни один кандидат не прошёл гейты прибыльности →
перевод в paper не производится. Корреляции внутри класса между активами
положительные (+0.10…+0.42) — «вторая копия того же риска» подтверждается.

## 4. Критерии перехода стадий

- research FAIL → гипотеза закрыта (запись в реестре), параметры не трогаются.
- research PASS → paper ≥ 4 недели на том же коде сигналов → сравнение с
  research-ожиданием → ТЕСТНЕТ с риск-лимитами P15/P64 → ≥ 20 сделок и 8 недель
  без нарушения инвариантов → только тогда отдельно обсуждать ограниченный live.
- Никакой автопереход по Sharpe. Запрещено торговать на реальном счёте без
  явного разрешения пользователя. Стат-арб/парный трейдинг в P68 не
  рассматривался: OHLCV-данных недостаточно для честной модели двух ног.

## 5. Зарегистрировано, но ещё не тестировано

- H3: сессионный фильтр для золота — нужен intraday-датасет XAUUSDT/PAXG.
- H4: funding-rate carry-фильтр поверх существующих стратегий — нужна история
  фандинга (Binance /fapi/v1/fundingRate).
- H5: парный spread ETH/BTC — нужна синхронная минутная история обеих ног.
- H6: false-break reversal («ложный пробой 1 баром», gerchik.com) — следующий
  прогон реестра.
