## Диагноз краша (по логу пользователя от 2026-11-09)

Симптом: cargo run --release --bin wfa_momentum -> 6 из 6 попыток
  exit code: 0xc0000005 (STATUS_ACCESS_VIOLATION) внутри rustc.exe,
  ни одной ошибки Rust (E0xxx) в логе, краш детерминированный.
Командная строка rustc из лога содержит: -C opt-level=3 -C lto
  -C codegen-units=1 -C strip=debuginfo  <- это [profile.release]
  из Cargo.toml проекта (opt-level=3, lto=true, codegen-units=1; SHA256
  71607214c7d2fa8dbc0a80829e04875eac6506f078ac734465ef047ef26a0694).
Вывод: падает сам компилятор на фазе fat-LTO кодогенерации/линковки
  (исходник к этому моменту уже успешно разобран и проверен типизатором —
  иначе были бы E0xxx, а не молчаливый STATUS_ACCESS_VIOLATION).
Код и данные P31 ни при чём: тот же wfa_momentum.rs (SHA256 совпадает с
  эталоном пакета P31) ранее прошёл все 6 эталонных прогонов и
  построчную кросс-валидацию с независимым референсом (см. VALIDATION_P31).

## Внешние подтверждения класса сбоя (проверено research-агентом, URL открыты)

- rust-lang/rust#85598: fat LTO валит rustc на Windows без внятного
  сообщения (LLVM умирает при нехватке памяти; bad_alloc не ловится).
- rust-lang/rust#88199: STATUS_ACCESS_VIOLATION на release-сборках
  x86_64-pc-windows-msvc.
- rust-lang/rust#143078 + тред users.rust-lang.org "Always
  STATUS_ACCESS_VIOLATION error in cargo build": третий фактор —
  AV/EDR-инъекции в процессы; лестница триажа: cargo clean, чистая
  переустановка тулчейна, исключения антивируса, проверка RAM.
- rust-lang/rust#134119: детерминированный 0xc0000005 даже на hello-world,
  закрыт как C-defective-hardware (битая RAM даёт такой же симптом).
- Cargo Book (doc.rust-lang.org/cargo/reference/profiles.html):
  lto=false отключает fat-LTO; кастомные профили ([profile.wfa] +
  inherits="release") стабильны с Cargo 1.57; наследование по-ключевое —
  явное lto=false перекрывает унаследованное lto=true.
- Cargo Book (environment variables): CARGO_PROFILE_RELEASE_LTO=off и
  CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16 — документированный override,
  принимает "off"/"false"/"thin"/"fat"/"true"; это даёт мгновенный обход
  без правки файлов.

## Ограничение валидации

Полной пересборки под новым профилем в песочнице не делалось: тулчейн Rust
в текущей сессии отсутствует (среда пересоздана), а Linux-сборка не
воспроизводит Windows-краш (эталонные прогоны P31 уже проходили на Linux
с этим же кодом). Риск низкий: P32 меняет только профиль сборки,
семантика кастомных профилей и override-переменных задокументирована
в Cargo Book. Приёмка на машине пользователя: числа прогонов должны
совпасть с эталонной таблицей README_P32 1:1 (f64-арифметика не зависит
от LTO).
