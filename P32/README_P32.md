# P32 — фикс краша компилятора (rustc STATUS_ACCESS_VIOLATION) для WFA momentum

Дата: 2026-11-09. Пак-фикс к P31. Код и данные P31 НЕ тронуты — P32 меняет
только конфигурацию сборки и добавляет два скрипта.

## Что случилось (диагноз)

При `cargo run --release --bin wfa_momentum` компиляция падала 6 из 6 раз:

```
error: could not compile `scalping_agents` (bin "wfa_momentum")
Caused by:
  process didn't exit successfully: ...rustc.exe ...
  (exit code: 0xc0000005, STATUS_ACCESS_VIOLATION)
```

В логе нет ни одной ошибки Rust (никаких `E0xxx`, никаких warning) — упал
сам компилятор, а не ваш код. Профиль `[profile.release]` собирает с fat LTO
(`lto = true`, `codegen-units = 1` — видно прямо в командной строке rustc из
вашего лога), а `wfa_momentum` линкует всю библиотеку бота (tokio, reqwest,
sqlx, ring, prometheus, ...). Whole-program LTO на таком объёме — известный
класс падений rustc/LLVM именно на Windows: LLVM умирает без внятного
сообщения при нехватке памяти или на багах бэкенда (rust-lang/rust#85598,
#88199; без ICE-сообщения — типичное поведение этого класса). У вас падение
детерминированное (6/6 на одном и том же месте) — значит, дело в режиме
сборки, а не в случайных сбоях.

## Что делает P32

Добавляет в `Cargo.toml` отдельный профиль сборки для исследовательских бинов:

```toml
[profile.wfa]
inherits = "release"
lto = false
codegen-units = 16
```

- `--profile wfa` собирается **без fat LTO** — краш устраняется, сборка ещё и
  быстрее (LTO-фаза была самой тяжёлой).
- Скорость самих WFA-прогонов практически не меняется: LTO экономит единицы
  процентов рантайма, для офлайн-исследования это некритично.
- **Боевой бот не затронут:** `[profile.release]` остаётся как был, сервер
  продолжает собираться ровно как раньше (P32 ничего в нём не меняет).
- Числа WFA не меняются: арифметика f64 детерминирована, LTO влияет только на
  кодогенерацию, не на результаты. Все цифры из README_P31/VALIDATION_P31
  обязаны сойтись 1:1 — это и есть приёмка P32.

## Установка (из корня проекта)

```powershell
Set-Location C:\Users\BASE_PC\scalping_agentsGLM
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\P32_wfa_nolto_20261109.zip" -DestinationPath . -Force
.\P32\apply_p32.ps1
```

Потом один командой запустить все 6 прогонов:

```powershell
.\P32\run_wfa_p32.ps1
```

`run_wfa_p32.ps1` сам проверит профиль (если забыли `apply_p32.ps1` — применит
его сам), пропустит отсутствующие CSV и в конце напечатает сводку. Логи
каждого прогона пишутся в `run_*.log` в корне проекта.

Важно: **первый** запуск под новым профилем пересоберёт все зависимости один
раз (несколько минут, ~2-3 ГБ в `target\wfa`) — это нормально, дальше кэш.

## Мгновенный обход (если нужно прямо сейчас, без пакета)

Официально задокументированный override профиля через переменные окружения —
в том же окне PowerShell:

```powershell
$env:CARGO_PROFILE_RELEASE_LTO = "off"
$env:CARGO_PROFILE_RELEASE_CODEGEN_UNITS = "16"
cargo run --release --bin wfa_momentum -- --data TAOUSDT-1h-full.csv --out run_taofull
```

Первая сборка после смены настроек тоже пересоберёт зависимости (один раз).
Действует до закрытия окна. Боевой сервер в этом окне не собирать — соберите
его в чистом окне, чтобы он остался на обычном release-профиле.

## План Б — если 0xc0000005 повторится даже без LTO

Лестница (после каждого шага — новая попытка
`cargo build --profile wfa --bin wfa_momentum`):

1. `cargo clean -p scalping_agents` — снести возможно битые артефакты.
2. `rustup update stable` — обновить тулчейн, затем чистая пересборка.
3. Память: закрыть браузеры/тяжёлые приложения, проверить свободную RAM
   (желательно 6-8+ ГБ свободно) и файл подкачки. Крайний случай —
   Windows Memory Diagnostic (`mdsched.exe`): битая RAM даёт 0xc0000005
   именно на компиляции (rust-lang/rust#134119, закрыт как дефект железа).
4. Антивирус: добавить исключения для папки проекта и `%USERPROFILE%\.cargo`
   (сторонние AV/EDR, внедряющиеся в процессы, роняют rustc —
   rust-lang/rust#143078 и разбор на users.rust-lang.org).
5. Если ничего не помогло — прислать мне три вещи:

```powershell
cargo build --profile wfa --bin wfa_momentum -v 2>&1 | Out-File -Encoding utf8 p32_fail.log
rustc --version
cargo --version
```

...плюс сам `p32_fail.log` — по нему будет видно, на какой фазе падает.
