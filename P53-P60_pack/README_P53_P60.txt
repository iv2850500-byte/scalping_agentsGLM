ЧТО ДЕЛАЕТ КАЖДЫЙ ПАК
---------------------
P53  H9 + C4.
     H9: ORDER_TRADE_UPDATE защитных ордеров (STOP_MARKET /
     TAKE_PROFIT_MARKET, FILLED) теперь закрывает позицию в state
     НЕМЕДЛЕННО, пишет PnL в риск-учёт, журнал, метрики, портфельный
     стоп и снимает выжившую защиту. Раньше биржевые закрытия были
     невидимы 5 минут, потом reconcile purge'ил позицию БЕЗ PnL.
     C4: сверка защит раз в 5 мин через /fapi/v1/openAlgoOrders:
     позиция жива, а SL/TP пропал -> WARN + восстановление;
     алго-защиты без позиции (сироты) -> снятие. Эндпоинт
     недоступен -> один warn, поведение прежнее.

P54  Портфельный дневной стоп = ЖЁСТКИЙ HALT.
     База теперь [global].account_capital_usdt (K6, у тебя 800) ->
     лимит 5% = 40.00 USDT, ровно как в check_k6. Раньше база была
     суммой initial_balance ботов - лимит не срабатывал никогда.
     Срыв записи daily PnL на диск = fail-CLOSED (входы стоят).
     Переход лимита = один Telegram-алерт. Гейт продублирован в
     ExecutionEngine (последняя инстанция перед POST). KILL-file
     проверка fail-closed (ошибка FS = входы запрещены).

P55  D2: периодический reconcile переведён на
     get_positions_authoritative() - без подмены локальным стейтом
     при сбоях positionRisk (STRICT=0). Фантомы/сироты/дрейф
     снова видимы; сбои честно пишутся в лог (p22-счётчик).

P56  S11 + тесты денежной математики. validate_rails() в движке:
     SL/TP обязаны быть конечными, положительными и на правильной
     стороне (Long: SL < entry < TP; Short: наоборот), иначе вход
     отбракован ДО ордера. Тесты: рельсы, семантика K6-бюджета
     (40 <= 40 молчит), линейность сайзинга, RR-формула.

P57  Liquidity-гейт: глубина книги в +/-0.10% от mid должна быть
     >= 500 USDT (OrderBook-стрим), иначе вход пропущен. Лечит
     главный источник утечки INJ: спред+импакт на тонкой книге.
     Нет данных стакана -> fail-open (depth=0 в diag).

P58  Объёмное подтверждение свипа: sweep-свеча обязана нести
     volume > 1.2 x avg20(предыдущих). Свип без объёма = шум.

P59  ATR-нормировка стопа + режимный гейт. Пол дистанции стопа =
     1.0 x ATR(14) (вик за пул бывает тонким - сайзинг раздувало);
     вик > 3xATR = структура сломана, пропуск. Вход только по
     тренду EMA50 собственного актива. ATR отдаётся в state -
     Chandelier-трейлинг теперь работает и у liquidity_grab.

P60  Equity-сайзинг: все 4 стратегии сайзятся от ЖИВОГО equity
     (initial + realized PnL) x режимного множителя (SURVIVAL 0.5 /
     GROWTH 1.0). Раньше канал P16 был мёртв: set_live_equity никто
     не звал, set_risk_multiplier не реализовал ни один бот - после
     просадки риск в % от фактического капитала РОС.

УСТАНОВКА
---------
1) Остановить бота (файлы заменяются на диске, бот держит exe,
   но не .rs - останавливать НЕ обязательно, но Cargo потом всё
   равно требует свободный exe; делаем всё сразу):
      Get-Process scalping_agents -ErrorAction SilentlyContinue | Stop-Process -Force
      Start-Sleep -Seconds 3
2) Распаковать P53-P60_pack.zip в КОРЕНЬ репозитория
   C:\Users\BASE_PC\scalping_agentsGLM (появится папка P53-P60_pack).
3) Применить:
      powershell -ExecutionPolicy Bypass -File .\P53-P60_pack\install_p53_p60.ps1
   Скрипт: бэкапы 14 файлов -> backups\<день>\*.bak-P53-60,
   замена файлов, дозапись v8-хвоста в check_packs.ps1, проверка
   маркеров (P53:32, P54:16, P55:1, P56:5, P57:4, P58:2, P59:7,
   P60:17). RESULT: OK - иначе restore из бэкапа.
4) Тесты и сборка:
      cargo test --lib          # 56 passed, 0 failed
      cargo build --release     # ~3.5 мин
5) Поднять:
      powershell -ExecutionPolicy Bypass -File .\deploy.ps1 -SkipBuild
6) Проверки:
      powershell -ExecutionPolicy Bypass -File .\check_packs.ps1
      powershell -ExecutionPolicy Bypass -File .\check_run.ps1

ПРИМЕЧАНИЯ
----------
- config.toml НЕ меняется (deny_unknown_fields не трогаем): все
  новые параметры - через env с рабочими дефолтами.
- C4/H9 активны только у futures-ботов Binance в реальном режиме
  (не simulate) - как user-stream сейчас.
- Периодический reconcile теперь честный: при флаках positionRisk
  тестнета тик пропускается с warn ("positionRisk недоступен,
  N подряд") - это НОРМАЛЬНО и лучше прежней молчаливой подмены.
- Если openAlgoOrders на тестнете ответит нестандартным JSON -
  C4 отключится с одним warn; пришли мне строку ответа, поправлю
  парсер хотфиксом P53.1.
